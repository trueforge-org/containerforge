## 4. Dockerfile

1. `FROM <python base>`, `ARG VERSION`, `USER root`.
2. `ENV HOME=/config PIP_CACHE_DIR=/tmp/pip FLASK_APP=main.py PYTHONUNBUFFERED=1`.
3. apt: `ffmpeg=7:8.0.1-3ubuntu2` pinned with `--no-install-recommends` (ffmpeg is a tool, not the app, so the pin only guards reproducibility; re-check the version at build with `apt-cache policy`, UNVERIFIED it stays available). Add `# hadolint ignore=DL3008`. Clean `/var/lib/apt/lists`.
4. Download `https://github.com/jo-nike/clipplex/archive/refs/tags/${VERSION}.tar.gz`, extract into `/app` with `--strip-components=1` so the package is at `/app/app` (required by the hardcoded paths); `rm` the tarball and `example.gif`, `Dockerfile`.
5. Install deps into `/app/venv`: `/app/venv/bin/pip install` with a relaxed requirements list generated by `sed` from upstream (keep `requests`, `ffmpeg-python==0.2.0`; replace the 2021 pins of Flask, Werkzeug, Jinja2, flask_wtf with current compatible releases, because Flask 2.0 / Jinja2 3.0 / Werkzeug 2.0.0 are unlikely to import on Python 3.15; UNVERIFIED, test import in the build with `python -c "import main"` is NOT possible without writing to `/app/app/static/media`, so use `python -c "import flask, flask_wtf, ffmpeg"`).
6. Make the media dir a symlink: `rm -rf /app/app/static/media && ln -s /config/media /app/app/static/media` (target created by `start.sh`). `chown -R root:root /app/app /app/main.py /app/clipplexAPI.py && chmod -R 755 ...`; do not touch `/app/venv` ownership beyond base.
7. License: `mkdir -p /usr/share/licenses/clipplex && cp /app/LICENSE /usr/share/licenses/clipplex/`.
8. `EXPOSE 5000`, `VOLUME /config`, `VOLUME /media`.
9. `COPY --chmod=0755 . /`.
10. Final line `USER apps`.

## 5. docker-bake.hcl

```hcl
target "docker-metadata-action" {}

variable "APP" {
  default = "clipplex"
}

variable "VERSION" {
  // renovate: datasource=github-releases depName=jo-nike/clipplex
  default = "0.0.3"
}

variable "LICENSE" {
  default = "MIT"
}

variable "SOURCE" {
  default = "https://github.com/jo-nike/clipplex"
}

group "default" {
  targets = ["image-local"]
}

target "image" {
  inherits = ["docker-metadata-action"]
  args = {
    VERSION = "${VERSION}"
  }
  labels = {
    "org.opencontainers.image.source" = "${SOURCE}"
    "org.opencontainers.image.licenses" = "${LICENSE}"
  }
}

target "image-local" {
  inherits = ["image"]
  output = ["type=docker"]
  tags = ["${APP}:${VERSION}"]
}

target "image-all" {
  inherits = ["image"]
  platforms = [
    "linux/amd64",
    "linux/arm64"
  ]
}
```
Validate with `docker buildx bake --print` from `apps/clipplex/`. Dockerfile `ARG VERSION` must receive exactly this value (no extra defaults).

```yaml
    required: true
  - path: /media
    required: false
opt_dependencies:

```
`PLEX_URL`/`PLEX_TOKEN` are functionally mandatory but marked `required: false` because the app starts without them (it reads them lazily per request) and the container test runs with no env; no empty `required: true` without default. Plex is an external server the user already runs, so it is listed as `opt_dependencies: - name: plex` (an `apps/plex` image exists ✅) rather than a hard dependency.

## 7. start.sh

1. `mkdir -p /config/media/videos /config/media/images` (idempotent; the app's `os.mkdir` then finds them).
2. `export FLASK_APP=main.py PYTHONDONTWRITEBYTECODE=1 TMPDIR=/tmp`.
3. `cd /app` (module paths `app/static/media` are relative to cwd).
4. If `PLEX_URL` or `PLEX_TOKEN` is empty, print a warning that the UI will load but clips fail.
5. `exec /app/venv/bin/python -m flask run --host 0.0.0.0 --port 5000` (the Flask dev server, as upstream; no debug mode). Secrets stay in the environment.

## 9. Rootless and read-only-rootfs adaptations

| Upstream write | Remap |
|---|---|
| `/app/app/static/media/{videos,images}` (README volume; chart PVC `clips`) | symlink `/app/app/static/media` -> `/config/media`; `start.sh` creates subdirs |
| pip cache, `__pycache__` | `/tmp`, `PYTHONDONTWRITEBYTECODE=1` |
| ffmpeg scratch | writes only into media dir and `/tmp` |
| `/media` | read-only bind mount recommended |

Draft expectation (non-root, read-only rootfs, clips PVC at `/app/app/static/media`) holds; clips are remapped to `/config/media`. Not privileged.

## 10. Risks, caveats and open questions

- Python 3.15 vs 2021 pins: relaxed pins may still need code changes (`flask_wtf` API, `cmath import e` in `clipplexAPI.py` is harmless). If the app cannot start, record as unfixable instead of lowering tests.
- Needs a reachable Plex server and token; the Plex-reported file paths must exist at the same absolute path under `/media`, otherwise ffmpeg fails.
- Hardcoded Flask `SECRET_KEY` and no authentication; clips under `/static/media` are publicly readable by anyone who reaches port 5000. Do not expose.
- Flask development server, single process (upstream author plans gunicorn "at some point").
- Hardcoded `/app/app/static/media` path means the symlink trick is mandatory; a future upstream change of path would break it.
- Hardcoded `PlexInfo("jonike")` user in the snapshot route (upstream debug leftover).

## 11. Build and test steps

Run per `build-test-protocol.instructions.md`, one app only, max 10 rounds:

```sh
cd apps/clipplex
docker buildx bake --print
docker buildx bake --set image-local.platform=linux/amd64 image-local
docker volume create clipplex-probe-config
docker run --rm -d --name clipplex-probe --read-only --tmpfs /tmp \
  -v clipplex-probe-config:/config clipplex:<VERSION>
docker logs -f clipplex-probe        # expect: Flask `Running on all addresses` / `Running on http://0.0.0.0:5000`
docker rm -f clipplex-probe; docker volume rm clipplex-probe-config
forgetool containers test --image clipplex:<VERSION> --config ./apps/clipplex/container-test.yaml
```

Always start from an empty `/config` volume and check that the container is still running, with no fatal errors or repeated stack traces. Attempt arm64 only if the amd64 loop is green or the failure is arm64-specific.
