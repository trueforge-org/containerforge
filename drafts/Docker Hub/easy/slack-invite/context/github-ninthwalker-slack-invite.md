## What it is
Small Express + Jade web app. A visitor enters an email and the server calls the Slack `users.admin.invite` API with a legacy token. Forked "for unraid usage" (Dockerfile comment); derived from outsideris/slack-invite-automation (README). Docker Hub text: "NOT FOR GENERAL USE".

## Install/build steps
Dockerfile (pinned commit):
- `FROM node:onbuild`
- `MAINTAINER ninthwalker`
- `EXPOSE 7879`
- `COPY . /slack-invite`
- `WORKDIR /slack-invite`
- `RUN npm install`
- `CMD ./bin/www`
- No USER, VOLUME, ENV, or start.sh.

## Binaries/entrypoint/CLI flags
- Start: `./bin/www` (or `node ./bin/www`).
- `bin/www`: loads `../.env` via dotenv if present; port from `PORT`, default 7879; `server.listen(port)` with no host (all interfaces). Errors: EACCES and EADDRINUSE exit 1.

## Routes (routes/index.js)
- `GET /`: sets locale, renders index.
- `POST /invite`: needs `email`; if `INVITE_TOKEN` is set, `token` must match. Calls Slack with form fields `email`, `token` (=SLACK_TOKEN), `set_active=true`. Body parsed with `JSON.parse(body)` with no try/catch. Handles `already_invited`, `already_in_team`, `invalid_email`, `invalid_auth` error codes.

## Gotchas
- `request` and `jade` are deprecated/old (package.json ranges).
- `JSON.parse(body)` on a non-JSON Slack reply throws inside the callback.
- README/Docker Hub say port 3000; code uses 7879.
- README and Docker Hub say the token must be generated by an admin, not the owner (missing_scope otherwise).
- The Slack endpoint `users.admin.invite` is not described as current in any fetched source; the README does not mention deprecation.
