## What it is
- Upstream release image for zerotier-one (ZeroTier daemon). Installs from ZeroTier's apt repo. Uses a shell entrypoint.

## Install/build steps (Dockerfile.release)
- `FROM debian:bookworm`, `ARG VERSION`
- `apt-get install curl gpg`
- Key: `curl -o /usr/share/zerotier/tmp.asc "https://download.zerotier.com/contact%40zerotier.com.gpg"`; `gpg --no-default-keyring --keyring /usr/share/zerotier/zerotier.gpg --import`; `rm tmp.asc`
- Repo: `/etc/apt/sources.list.d/zerotier.list` = `deb [signed-by=/usr/share/zerotier/zerotier.gpg] http://download.zerotier.com/debian/bookworm bookworm main`
- `apt-get install zerotier-one=${VERSION} curl iproute2 net-tools iputils-ping openssl libssl3 -y`
- `rm -rf /var/lib/zerotier-one`
- `COPY entrypoint.sh.release /entrypoint.sh`; `chmod 755`
- `HEALTHCHECK --interval=1s CMD bash /healthcheck.sh`; `CMD []`; `ENTRYPOINT ["/entrypoint.sh"]`

## Runtime deps
- zerotier-one (apt, pinned by `VERSION`), curl, iproute2, net-tools, iputils-ping, openssl, libssl3.

## Entrypoint/flags (entrypoint.sh.release, /bin/sh)
- Command-line args: network ids. Each is `touch /var/lib/zerotier-one/networks.d/<id>.conf`.
- Writes `/var/lib/zerotier-one/zerotier-one.port` = `9993` (mode 0600).
- Starts `nohup /usr/sbin/zerotier-one &`; waits until `/var/lib/zerotier-one/zerotier-one.pid` process exists.
- Generates `/healthcheck.sh` at runtime: for each network id (args + `ZEROTIER_JOIN_NETWORKS`), `zerotier-cli get <id> status` must equal `OK`.
- Logs `zerotier-cli info`, then `while true; sleep 1`.
- `trap killzerotier INT TERM` -> `kill` pidfile process, exit 0.

## Env vars (entrypoint.sh.release)
| Var | Effect |
| --- | --- |
| ZEROTIER_API_SECRET | written to `/var/lib/zerotier-one/authtoken.secret` (0600) |
| ZEROTIER_IDENTITY_PUBLIC | written to `identity.public` (0644) |
| ZEROTIER_IDENTITY_SECRET | written to `identity.secret` (0600) |
| ZEROTIER_JOIN_NETWORKS | space-separated network ids, touched into networks.d |

- Writes use `echo "$content"` (trailing newline).
- No `ZEROTIER_LOCAL_CONF` and no `metricstoken.secret` in upstream entrypoint.

## Ports
- Not in Dockerfile. Daemon default 9993 (written to zerotier-one.port).

## Volumes/paths
- `/var/lib/zerotier-one` (state, identity, networks.d). Removed from image (`rm -rf`) and created at runtime.

## User/UID
- Not set (root).

## Config files
- `/var/lib/zerotier-one/{authtoken.secret, identity.public, identity.secret, zerotier-one.port, networks.d/*.conf}`

## Healthcheck
- Dockerfile: `HEALTHCHECK --interval=1s CMD bash /healthcheck.sh`. The script itself is generated by entrypoint at runtime.

## Version/asset naming
- `VERSION` build arg selects the apt package version (`zerotier-one=${VERSION}`).

## Arch
- Not stated in these files.

## Gotchas
- Base is `debian:bookworm`, apt suite `bookworm` (not `resolute`). Plan uses `resolute` (Ubuntu 26.04).
- Upstream runs the daemon in background via nohup; entrypoint loops with `sleep` (not exec).
- `CMD []` and `ENTRYPOINT ["/entrypoint.sh"]`; network ids come via command args.
