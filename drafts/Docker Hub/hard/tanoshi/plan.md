## 4. Dockerfile

1. Builder: `FROM <ubuntu digest> AS builder`, `ARG VERSION`, `USER root`, `ENV HOME=/tmp CARGO_HOME=/tmp/cargo RUSTUP_HOME=/tmp/rustup CARGO_TARGET_DIR=/tmp/target`.
2. apt (builder only): `curl ca-certificates build-essential pkg-config libssl-dev libxml2-dev nettle-dev git` (inferred from the upstream runtime libs; UNVERIFIED completeness, confirm by building).
3. Toolchain: install rustup, `rustup toolchain install 1.99.1 --target wasm32-unknown-unknown`, `cargo install trunk` (pin its version from the upstream builder repo `luigi311/tanoshi-builder`, UNVERIFIED) and `wasm-bindgen-cli` if trunk does not fetch it.
4. Source: `ADD https://github.com/luigi311/tanoshi.git#v${VERSION} /src`, `WORKDIR /src`; `cd crates/tanoshi-web && trunk build --release`; `cargo build -p tanoshi --release --locked`.
5. Runtime stage: `ARG VERSION`, `USER root`, apt `ca-certificates libssl3t64 libxml2 libnettle8t64 tini` only if the base lacks them (check first; upstream names `libssl3` and `libxml2-dev`, resolve the real package names on 26.04); pin nothing unless an apt package defines the version.
6. `COPY --from=builder /tmp/target/release/tanoshi /app/tanoshi`, `chmod 755`; `COPY --from=builder /src/LICENSE /usr/share/licenses/tanoshi/LICENSE`.
7. `ENV TANOSHI_HOME=/config HOME=/config TANOSHI_LOG=info`, `EXPOSE 8080`, `VOLUME /config`, `COPY --chmod=0755 . /`, last: `USER apps`, `COPY --chmod=0755 . /`.
8. Per Dockerfile rules the Rust build is in its own stage; nothing compiled in the runtime stage.

## 7. start.sh

```bash
#!/usr/bin/env bash
set -euo pipefail
export TANOSHI_HOME="${TANOSHI_HOME:-/config}"
mkdir -p "$TANOSHI_HOME"/{plugins,downloads,cache,manga}
if [ ! -s "$TANOSHI_HOME/config.yml" ]; then
  umask 077
  cat > "$TANOSHI_HOME/config.yml" <<EOF
port: ${PORT:-8080}
secret: "$(head -c 32 /dev/urandom | base64 | tr -d '\n')"
database_path: "$TANOSHI_HOME/tanoshi.db"
plugin_path: "$TANOSHI_HOME/plugins"
local_path: "$TANOSHI_HOME/manga"
download_path: "$TANOSHI_HOME/downloads"
cache_path: "$TANOSHI_HOME/cache"
EOF
fi
exec /usr/bin/tini -- /app/tanoshi --config "$TANOSHI_HOME/config.yml"
```
Idempotent, never overwrites an existing config, nothing written to `/app`. UNVERIFIED: that the server binds 0.0.0.0 (the `base_url`/`port` semantic); verify with a connection from outside the container, and add the bind setting if config exposes one. Cache dir could alternatively be `/tmp/tanoshi-cache` (preferred if the app tolerates loss; caches belong in `/tmp`): use `/tmp` for `cache_path` instead of `/config` and drop it from the mkdir.

## 9. Rootless and read-only-rootfs adaptations

- Upstream: root (draft chart runAsUser 0, rootfs writable), data in `/tanoshi`. Here: `USER apps`, `TANOSHI_HOME=/config`, binary read-only in `/app`.
- Write paths: DB, plugins, downloads, manga, config -> `/config`; cache -> `/tmp`. Upstream default data dir otherwise falls to `~/.local/share/tanoshi`; `HOME=/config` covers any stray write.
- Draft "extra persistence /tanoshi" is replaced by `/config` (migration note for existing users: mount old `/tanoshi` content there).

## 10. Risks, caveats and open questions

- Long build with wasm32 target and trunk; high RAM/disk use, slow under QEMU for arm64. Consider native arm64 runners.
- Upstream uses a prebuilt builder image (`tanoshi-builder`); reproducing it needs trunk/wasm-bindgen versions that UNVERIFIED here.
- Draft port 3579 vs upstream `PORT=80`; real default unverified.
- Project is maintained by a successor fork (luigi311), not the original author; the draft's `faldez` image is stale. Extensions/plugins are fetched from the network at runtime.
- Release artifacts are Tauri desktop builds, so no prebuilt server binary: compile on both arches. No musl, GPU or privileged blockers.
