# AlistGo/alist (upstream source, releases, Dockerfile, entrypoint)

**Source URL(s) + fetch date:** https://github.com/AlistGo/alist (raw `main/README.md`, raw `main/Dockerfile`, raw `main/entrypoint.sh`, https://github.com/AlistGo/alist/releases/latest) · fetched 2026-11-26

## What it is
"A file list program that supports multiple storages, powered by Gin and Solidjs." Many storage backends (local, OneDrive, Google Drive, S3, FTP/SFTP, WebDAV, SMB, Dropbox, Azure Blob, etc.), previews, WebDAV, offline download, multi-thread download, dark mode, i18n. AGPL-3.0.

## Install/build steps and build deps
Upstream Dockerfile is two-stage:
- Builder: `FROM alpine:edge`, `apk add bash curl gcc git go musl-dev`, `go mod download`, `bash build.sh release docker`. Output `/app/bin/alist`.
- Final: `FROM alpine:edge`; `ARG INSTALL_FFMPEG=false`, `ARG INSTALL_ARIA2=false`; `WORKDIR /opt/alist/`; `apk add bash ca-certificates su-exec tzdata`.
- If `INSTALL_FFMPEG=true`: `apk add ffmpeg`.
- If `INSTALL_ARIA2=true`: `apk add curl aria2`; downloads P3TERX `aria2.conf` master tarball; `sed` comments `rpc-secret`; rewrites `/root` paths to `/opt/aria2`; touches `aria2.session`; runs `tracker.sh`.
- `COPY --chmod=755 --from=builder /app/bin/alist ./`; `COPY --chmod=755 entrypoint.sh /entrypoint.sh`; `RUN /entrypoint.sh version`.

## Runtime deps
Final image: bash, ca-certificates, su-exec, tzdata (plus ffmpeg/aria2 if enabled).

## Binaries/entrypoint/CLI flags
- `CMD [ "/entrypoint.sh" ]` (no ENTRYPOINT, no USER in Dockerfile).
- entrypoint.sh: `umask ${UMASK}`; if `$1 = version` runs `./alist version`; else if `RUN_ARIA2=true`, `chown -R PUID:PGID /opt/aria2/` and starts `aria2c --enable-rpc --rpc-allow-origin-all --conf-path=/opt/aria2/.aria2/aria2.conf` in background via su-exec; then `chown -R PUID:PGID /opt/alist/` and `exec su-exec PUID:PGID ./alist server --no-prefix`.
- Note: upstream runs with `--no-prefix`, so env names are not `ALIST_`-prefixed in the upstream image.

## Env vars
| Name | Default | Purpose |
| --- | --- | --- |
| `PUID` | `0` | uid the process is switched to via su-exec |
| `PGID` | `0` | gid |
| `UMASK` | `022` | umask |
| `RUN_ARIA2` | = `INSTALL_ARIA2` (build arg, default false) | start aria2c in the background |
| `TZ` | UTC (per docs) | timezone |

## Ports
`EXPOSE 5244 5245`. Web UI/API on 5244.

## Volumes/paths and persistent data
`VOLUME /opt/alist/data/` (docs: host `/etc/alist` mounted there). Working dir `/opt/alist/`. With aria2: `/opt/aria2/.aria2/` (aria2.conf, session, script.conf).

## User/UID & permissions
Defaults PUID=0 PGID=0 (root). entrypoint uses su-exec to drop to PUID:PGID after chown.

## Gotchas
- Upstream Dockerfile is alpine-based; plan.md uses ubuntu base. Expected for a port.
- `entrypoint.sh` uses `--no-prefix`; the plan's `ALIST_*` env design requires not passing `--no-prefix`.
- Admin password: docs (see alistgo-docs-install-docker.md) say the password is not logged at first start.

## Contradictions with plan.md
- plan.md section 1 says the upstream entrypoint runs `./alist server --no-prefix`: confirmed.
- plan.md section 1 says `VOLUME /opt/alist/data/`, `EXPOSE 5244 5245`, `ENV PUID=0 PGID=0 UMASK=022`: confirmed.
- plan.md section 1 says "Alist generates a random admin password on first start and logs it": not supported by the docs, which describe `./alist admin` and `admin random` instead (see the docs summary).
