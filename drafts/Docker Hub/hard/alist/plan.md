## 3. Base image

`FROM ghcr.io/trueforge-org/ubuntu:26.04@sha256:19cb2ceefb7364eed299290b4f4270d50a2eaa9393b0002b267f5b4f13926454`

## 4. Dockerfile

1. `ARG VERSION`, `ARG TARGETARCH` (values `amd64` / `arm64` match the asset names, no mapping needed). `USER root`.
2. `ENV HOME=/tmp` (alist and aria2 write nothing to `$HOME` by design, keep it off `/app`).
3. `apt-get update && apt-get install -y --no-install-recommends aria2 ca-certificates` then clean `/var/lib/apt/lists`. Check first whether `ca-certificates` is already in the base and skip it if so. Pin the aria2 version only if `apt-cache policy aria2` on the base gives a stable value, otherwise leave unpinned (aria2 is a helper, not the tagged software).
4. Download and verify:
   ```dockerfile
   RUN curl -fsSL -o /tmp/alist.tar.gz "https://github.com/AlistGo/alist/releases/download/v${VERSION}/alist-linux-${TARGETARCH}.tar.gz" && \
       curl -fsSL -o /tmp/md5.txt "https://github.com/AlistGo/alist/releases/download/v${VERSION}/md5.txt" && \
       (cd /tmp && grep " ./alist-linux-${TARGETARCH}.tar.gz$" md5.txt | sed 's#\./##' | md5sum -c -) && \
       mkdir -p /app /usr/share/licenses/alist && \
       tar xzf /tmp/alist.tar.gz -C /app alist && \
       curl -fsSL -o /usr/share/licenses/alist/LICENSE "https://raw.githubusercontent.com/AlistGo/alist/v${VERSION}/LICENSE" && \
       chown -R apps:apps /app && chmod -R 755 /app && rm -f /tmp/alist.tar.gz /tmp/md5.txt
   ```
5. Only the `alist` binary is extracted, so the AGPL `LICENSE` is shipped separately to `/usr/share/licenses/alist/`.
6. `USER apps`, `COPY --chmod=0755 . /`, `EXPOSE 5244` (6800 is not exposed or listed in `settings.yaml` while aria2 is opt-in), `VOLUME /config`.
7. Do not add `INSTALL_FFMPEG`; it is an upstream opt-in and out of scope.

## 6. settings.yaml

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/trueforge-org/forgetool/refs/heads/main/schemas/container-settings.schema.json
schema_version: 1
upstream_env_url: "https://github.com/AlistGo/alist/"
ports:
  - {port: 5244, protocol: tcp, required: false}
env:
  - {name: TZ, default: "Etc/UTC", required: false}
  - {name: ALIST_SITE_URL, default: "", required: false}
  - {name: ENABLE_ARIA2, default: "false", required: false}
  - {name: ARIA2_RPC_SECRET, default: "", required: false}
volumes:
  - {path: /config, required: true}
```

Write it in the sibling list style (one key per line, as in `apps/mariadb/settings.yaml`). No `dependencies:` (the draft lists none). Port 6800 is deliberately not listed: aria2 is off by default, so the container does not open it in the test run, and every listed port needs a probe. `ENABLE_ARIA2` is documented as an env var only; add 6800 to `ports` and a `tcp` probe only if aria2 is made default-on.

## 7. start.sh

1. `#!/usr/bin/env bash`; `mkdir -p /config /tmp/aria2 /config/downloads` (idempotent).
2. Do not write config: alist creates `/config/config.json` and `/config/data.db` itself when the data dir is empty. Never overwrite an existing `config.json`.
3. If `ENABLE_ARIA2=true`: if `ARIA2_RPC_SECRET` is empty, generate one with `head -c 24 /dev/urandom | base64` and log that a secret was generated (but not its value). Write `/tmp/aria2/aria2.conf` with mode 600 containing `enable-rpc=true`, `rpc-listen-all=true`, `rpc-listen-port=6800`, `rpc-secret=<secret>`, `dir=/config/downloads`, `input-file`/`save-session=/config/aria2.session`, `continue=true`. Using a conf file keeps the secret out of the process list. Start `aria2c --conf-path=/tmp/aria2/aria2.conf &` in the background. Upstream's P3TERX conf with the `rpc-secret` commented out leaves RPC open, which this plan deliberately avoids.
4. Seed the bind address once: if `/config/config.json` exists, do nothing. Otherwise let alist create it, which already defaults to `scheme.address = 0.0.0.0` and `http_port = 5244` (verified in `DefaultConfig`).
5. Final command (no `--no-prefix`, so `ALIST_*` env names apply): `cd /app && exec /app/alist server --data /config`.
6. Note `PUID`/`PGID`/`UMASK` from upstream are not used; the container always runs as `apps`.

## 9. Rootless and read-only-rootfs adaptations

| Upstream write path | Remap |
| --- | --- |
| `/opt/alist/data/` (config.json, data.db, log, temp, bleve) | `--data /config`. Log, temp and index dirs derive from the data dir, so they persist under `/config`. Set `ALIST_TEMP_DIR=/tmp/alist` in `start.sh` to keep scratch out of `/config`. |
| `/root/.aria2` (conf, session) | conf in `/tmp/aria2`, session in `/config/aria2.session`. |
| aria2 download dir | `/config/downloads` (chart used the data PVC; no separate `/data`). |
| `PUID=0 PGID=0`, chart `runAsUser: 0` | Drop it. The image runs as `apps` with `readOnlyRootFilesystem` compatible paths. The draft's "supervisor rework" is not needed: `start.sh` backgrounds aria2 and `exec`s alist. |

The chart persisted `/opt/alist/data`; the new image uses `/config` only, so migration needs the volume remounted to `/config`.

## 10. Risks, caveats and open questions

- Draft says the image bundles aria2 with an open RPC; this plan makes aria2 opt-in with a required secret. Confirm that is acceptable.
- If aria2 dies, alist keeps running (background process, no supervisor). Acceptable for an optional helper; document it.
- Only md5 is published, so supply-chain verification is weak. Consider pinning a sha256 in the Dockerfile (computed when the version is bumped), but renovate would not update it. Not recommended; keep md5.
- Project governance concerns around AlistGo and the OpenList fork exist (UNVERIFIED, not checked here). Re-check the upstream status before porting.
- The version gap (3.41.0 in the chart vs 3.66.0) means database migrations run on first start for existing users.
- The scheme env var prefix is UNVERIFIED (section 1).

## 11. Build and test steps

Run from the repo root, one app only, in this order (per `build-test-protocol.instructions.md`):

```sh
cd apps/alist
docker buildx bake --print
docker buildx bake --set image-local.platform=linux/amd64 image-local
docker run --rm -d --name alist-probe --read-only --tmpfs /tmp \
  -v alist-probe-config:/config alist:3.66.0
docker logs -f alist-probe        # expect: the HTTP server listening on 0.0.0.0:5244 and a generated admin password line
cd ../.. && forgetool containers test --image alist:3.66.0 --config ./apps/alist/container-test.yaml
docker rm -f alist-probe; docker volume rm alist-probe-config
```

- Fresh named volume every round. Round limit 10.
- Separately run once with `-e ENABLE_ARIA2=true` and confirm port 6800 answers a JSON-RPC `aria2.getVersion` call with and without the secret (the test suite cannot do this).
- Check the first-start log for the admin password and that no writes fail on the read-only rootfs.
