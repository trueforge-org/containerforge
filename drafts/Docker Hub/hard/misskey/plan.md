## 4. Dockerfile

Stage `build` (python-node):
1. `ARG VERSION`, `ARG TARGETARCH`, `ARG SRC_SHA256`, `USER root`, `ENV NODE_ENV=production`.
2. `apt-get install -y --no-install-recommends build-essential` (probably present, check), clean lists.
3. Download the tag tarball, check `SRC_SHA256`, extract to `/app/misskey --strip-components=1`.
4. `corepack`-style install of the pinned pnpm: `node -e "console.log(JSON.parse(require('node:fs').readFileSync('./package.json')).packageManager)" | xargs npm install -g` (the upstream approach). Set `npm_config_cache=/tmp/.npm`, `PNPM_HOME` and the pnpm store to `/tmp/pnpm-store`.
5. `pnpm i --frozen-lockfile --aggregate-output && pnpm build`. Frontend build is RAM heavy (UNVERIFIED how much; plan for 4 GB or more of build memory).
6. Prune: `rm -rf .git`, then `pnpm i --frozen-lockfile --prod` for backend only if it works with the workspace (UNVERIFIED), or copy the upstream pattern (separate target-arch stage that installs only `packages/backend` and the two small packages' deps). Prefer copying upstream's two-stage approach, since it is proven.

Final stage (python-node):
- `USER root`; `apt-get install -y --no-install-recommends ffmpeg tini libjemalloc2` (skip what the base has) and `ln -s /usr/lib/$(uname -m)-linux-gnu/libjemalloc.so.2 /usr/local/lib/libjemalloc.so`.
- `COPY --from=build --chown=apps:apps /app/misskey /app/misskey`.
- Symlink writable paths to `/config`: `rm -rf /app/misskey/files && ln -s /config/files /app/misskey/files`. A symlink target that does not exist yet is fine, `start.sh` creates it.
- License: `install -D /app/misskey/LICENSE /usr/share/licenses/misskey/LICENSE`.
- `ENV HOME=/config NODE_ENV=production LD_PRELOAD=/usr/local/lib/libjemalloc.so XDG_CACHE_HOME=/tmp/.cache PNPM_CONFIG_VERIFY_DEPS_BEFORE_RUN=false MISSKEY_CONFIG_YML=/config/default.yml`.
- `USER apps`, `COPY --chmod=0755 . /`, `EXPOSE 3000`, `VOLUME /config`.

## 6. settings.yaml

- Header, `schema_version: 1`, `upstream_env_url: "https://github.com/misskey-dev/misskey"`.
- `ports`: 3000 tcp, required false.
- `env` (names verified in `config.ts`; the host and redis names are our own and are used only by `start.sh`):

  - `MISSKEY_URL` (empty, required true, the public HTTPS URL; do not change it after the first start)
  - `PORT` (`3000`)

  - `DATABASE_HOST` (`postgresql`) and `DATABASE_PORT` (`5432`) are read by `start.sh` and written to the yml
  - `REDIS_HOST` (`valkey`), `REDIS_PORT` (`6379`), `REDIS_PASSWORD` (empty) are read by `start.sh`
- `volumes`: `/config` required (config yml, `files/`). The chart's `/misskey/files` PVC maps to `/config/files`, and its `.config` configmap maps to `/config/default.yml`.
- `dependencies`: `postgresql` ✅, `valkey` ✅.

## 7. start.sh

```bash
#!/usr/bin/env bash
set -euo pipefail
mkdir -p /config/files /tmp/.cache
cd /app/misskey
if [[ -z "${MISSKEY_URL:-}" || -z "${DATABASE_PASSWORD:-}" ]]; then
  echo "MISSKEY_URL and DATABASE_PASSWORD are not set; starting a stub server on :${PORT:-3000}"
  exec node -e "require('http').createServer((q,r)=>{r.writeHead(200);r.end('Misskey needs MISSKEY_URL, DATABASE_PASSWORD, PostgreSQL and Valkey')}).listen(${PORT:-3000},'0.0.0.0')"
fi
if [[ ! -s /config/default.yml ]]; then
  umask 077
  {
    echo "db:"
    echo "  host: '${DATABASE_HOST:-postgresql}'"
    echo "  port: ${DATABASE_PORT:-5432}"
    echo "redis:"
    echo "  host: '${REDIS_HOST:-valkey}'"
    echo "  port: ${REDIS_PORT:-6379}"
    [[ -n "${REDIS_PASSWORD:-}" ]] && echo "  pass: '${REDIS_PASSWORD//\'/\'\'}'"
    echo "id: 'aidx'"
  } > /config/default.yml
fi
exec /usr/bin/tini -- node scripts/start.mjs --migrate
```
Design points:
- `url`, `port` and the db name, user and password are left out of the yml on purpose. `config.ts` then falls back to `MISSKEY_URL`, `PORT`, `DATABASE_DB`, `DATABASE_USER`, `DATABASE_PASSWORD` (fallback verified in the source), so changed env values apply on every start and the DB password never lands in a file.
- The yml is seeded only when missing. The db host and port and all Redis settings can only live in the yml, so later changes to `DATABASE_HOST` or `REDIS_*` need the user to edit `/config/default.yml`. UNVERIFIED: if this is too surprising, regenerate the file on every start from env when it carries a marker comment.
- Quote and escape YAML values (the snippet escapes single quotes in the Redis password).
- `id: 'aidx'` must never change after the first start.
- The stub server keeps port 3000 probeable with no env, as `apps/mastodon` does.
- Final command is `exec ... node scripts/start.mjs --migrate`, wrapped in `tini`.

## 9. Rootless and read-only-rootfs adaptations

| Upstream write path | Remap |
|---|---|
| `/misskey/files` (drive) | `/app/misskey/files` is a symlink to `/config/files` |
| `/misskey/.config/default.yml` | `MISSKEY_CONFIG_YML=/config/default.yml` |
| `/misskey/built`, `node_modules` | read-only in `/app`, only read at runtime |
| npm, pnpm and Node caches, `HOME` | `/tmp/.cache`, `/tmp/pnpm-store`; `HOME=/config` |
| Upstream user `misskey` uid 991 | we run as `apps` (568) |

The draft expects root (UID 0, readOnlyRootFilesystem false, fsGroup 33). Reject: run as 568 with a read-only rootfs. Drive files are the only persistence, plus the config. `fsGroup 33` goes away; the volume must be writable by 568.

## 10. Risks, caveats and open questions

- Long and RAM-heavy build (frontend and `pnpm build` over many packages). arm64 builds under emulation may time out in CI.
- UNVERIFIED: the Node version on `python-node` (needs 26.13.1 per `.node-version`), the pnpm 12.x install, and whether pruning dev dependencies works with the workspace.
- A federation instance needs a public HTTPS domain, and `url` and `id` cannot change after first start.
- A DB password on the environment is passed to the process, and the Redis password lands in `/config/default.yml` (mode 600).
- The stub server adds a code path that only exists for tests and unconfigured starts. It is the same trade-off `apps/mastodon` made.
- Chart ties to PostgreSQL (cnpg) and Valkey: both containers exist (✅).
- Upstream's `ffmpeg` is needed for video thumbnails.
