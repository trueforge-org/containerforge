## 4. Dockerfile

1. `ARG VERSION`, `FROM` the steamcmd base as in section 3. No `ARG TARGETARCH` needed: amd64 only.
2. `USER root` is not needed: no install step. Keep the file minimal.
3. `COPY --chmod=0755 start.sh /start.sh` (same as the steamcmd sibling), then `USER apps`.
4. `ENV HOME=/config`, `XDG_DATA_HOME=/config`, `TMPDIR=/tmp`.
5. Final:

```dockerfile
ARG VERSION
FROM ghcr.io/trueforge-org/steamcmd:20180105-5build1@sha256:<digest UNVERIFIED>
ARG VERSION
ENV HOME=/config XDG_DATA_HOME=/config TMPDIR=/tmp
COPY --chmod=0755 start.sh /start.sh
USER apps
COPY --chmod=0755 . /
VOLUME /config
```

- The `ARG VERSION` line must match `docker-bake.hcl`. Do not `EXPOSE` the Steam ports until they are confirmed.
- The server binary path is set at start in `start.sh` (section 7), not here.

## 7. start.sh

```bash
#!/usr/bin/env bash
set -euo pipefail

export HOME=/config
export XDG_DATA_HOME=/config
mkdir -p /config/barotrauma

# Install or update the server via the steamcmd base wrapper (STEAM_APP_IDS, STEAM_INSTALL_DIR).
# The base start.sh runs SteamCMD and then execs steamcmd itself, so the Barotrauma launch
# must be a separate step (UNVERIFIED binary path and arguments).

exec /config/barotrauma/<server-binary> <args UNVERIFIED>
```

- Idempotent: the steamcmd base already handles the empty-`/config` case (creates `/config/steamcmd` and `/config/Steam/steamcmd`). Barotrauma install lands in `STEAM_INSTALL_DIR`.
- Writes only to `/config` and `/tmp`. Nothing to `/app`.
- Seeding `serversettings.xml`: UNVERIFIED whether the server generates it on first start. If it does not, seed a minimal file only when missing (no overwrite).
- The steamcmd base `start.sh` `exec`s SteamCMD at the end when no `+` arguments are given. Our `start.sh` must either call the base with `/start.sh +quit`-style arguments first, or source the install step. Choose once the flow is verified; do not run SteamCMD twice per start without need.
- Use `exec` for the final server binary so signals propagate.

## 9. Rootless and read-only-rootfs adaptations

| Upstream write path (ich777 wrapper) | Remap |

| `UMASK=000`, `DATA_PERM=770` (wrapper) | Not carried over: no root wrapper. Files are owned by `apps`. |

Draft security expectations reconciled: chart runs as UID 0 (wrapper), this image runs as `apps`, `readOnlyRootFilesystem` compatible if Steam state is under `/config` and scratch under `/tmp`. Not privileged. Chart's `/serverdata/serverfiles` and `/serverdata/steamcmd` PVCs map to `/config` (one volume; migration note for existing chart users).
