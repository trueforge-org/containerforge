## 4. Dockerfile

1. Base stage: `FROM ghcr.io/trueforge-org/python-node:3.15.2@sha256:... AS base`, `USER root`, `RUN npm install -g pnpm@11.28.9`. Set `ENV HOME=/tmp COREPACK_HOME=/tmp/corepack` so caches land in `/tmp`.
2. Source stage: `ARG VERSION`, fetch `https://github.com/bookorbit/bookorbit/archive/refs/tags/${VERSION}.tar.gz` into `/src` (`tar xz --strip-components=1`). Do not use a git clone (no history needed).
3. Client build (`client-builder`): copy `package.json pnpm-workspace.yaml pnpm-lock.yaml patches/ packages/types/package.json client/package.json`, then `pnpm install --filter client... --frozen-lockfile` with the pnpm store at `/tmp/pnpm`. Then `pnpm --config.verify-deps-before-run=false --filter client run build-only`. Copy `client/dist` out.
4. Server build (`server-builder`): same pattern with `server`. Run `pnpm --config.verify-deps-before-run=false --filter server run build`, then `pnpm --config.allow-unused-patches=true --filter server deploy --prod --legacy /deploy`. Copy `server/dist`, `server/src/db/migrations`, `server/entrypoint.sh` and `server/file-env.sh` from upstream.
5. Python venv: `python3 -m venv /opt/bookorbit-python`, then `pip install --no-cache-dir -r server/requirements/kobo-cloudscraper.txt` in the build stage. Do not uninstall pip in a way that leaves the venv broken. Use `--no-cache-dir` so the cache is not kept.
6. Final stage: `FROM python-node:... AS runtime`, `ARG VERSION`, `USER root`.
7. Apt packages (only those not already in the base; check first with `dpkg -l`): `poppler-utils`, `djvulibre-bin`, `ffmpeg`, `util-linux`, `tini`, `tzdata`. UNVERIFIED: package names in the 26.04 archive. `su-exec` and `py3-pip` are Alpine names and are not used. `apt-get install --no-install-recommends ...` then `rm -rf /var/lib/apt/lists/*`.
8. `COPY --from=venv` the `/opt/bookorbit-python` venv (same base digest, so the interpreter path matches).
9. `COPY --from=server-builder --chown=apps:apps /deploy ./` into `/app`, then `COPY --from=server-builder /src/server/dist`, `/src/server/entrypoint.sh`, `/src/server/file-env.sh`, `/src/client/dist ./public`, `/src/client/src/locales ./locales`, `/src/server/bin/kepubify/`, `/src/server/vendor/foliate/`, `/src/koreader-plugin/bookorbit.koplugin/` as upstream does. Copy `LICENSE`, `NOTICE`, `ADDITIONAL_TERMS.md` to `/app/` and to `/usr/share/licenses/bookorbit/`.
10. Line endings: `sed -i 's/\r$//' /app/entrypoint.sh /app/file-env.sh` (upstream does this). `chmod +x` on `bin/kepubify/*`.
11. Remap write paths with build-time symlinks (see section 9): `RUN ln -s /config/data /data && ln -s /config/books /books` while still `USER root`. The root filesystem is writable at build time only, so this must not be done in `start.sh`.
12. Environment: `ENV NODE_ENV=production PORT=3000 NODE_MAX_OLD_SPACE_SIZE=2048 APP_VERSION=${VERSION} KOBO_CLOUDSCRAPER_PYTHON=/opt/bookorbit-python/bin/python KOREADER_PLUGIN_PATH=/app/koreader-plugin/bookorbit.koplugin`. Do not set `JWT_SECRET` in the image.
13. Tail:

```dockerfile
EXPOSE 3000
VOLUME /config
USER apps
COPY --chmod=0755 . /
WORKDIR /app
```

`CMD ["/start.sh"]`. `start.sh` uses `exec`, so the Node process is PID 1 and gets signals directly. Use `ENTRYPOINT ["/usr/bin/tini","-s","--"]` only if the signal test in section 11 shows the Node process does not handle SIGTERM as PID 1 (UNVERIFIED). If tini is used, keep it installed in step 7.

## 7. start.sh

Idempotent, `exec`s the server, no root branch:

```bash
#!/bin/sh
set -eu

mkdir -p /config/data/covers /config/data/book-bucket /config/books
[ -w /config/data ] || { echo "bookorbit: /config/data is not writable" >&2; exit 1; }

: "${JWT_SECRET:?JWT_SECRET is required}"
: "${SETUP_BOOTSTRAP_TOKEN:?SETUP_BOOTSTRAP_TOKEN is required}"

export NODE_MAX_OLD_SPACE_SIZE="${NODE_MAX_OLD_SPACE_SIZE:-2048}"
cd /app
node dist/scripts/migrate.js
exec node --max-old-space-size="$NODE_MAX_OLD_SPACE_SIZE" dist/main.js
```

Rules: `mkdir -p` only creates missing dirs, never overwrites. Secrets come from env and are never written to disk or to the command line (`exec node` keeps them in the environment only). Decision for the maintainer: refuse to start (above, simplest and matches "required: true") versus generate `JWT_SECRET` into `/config/secrets` on first run (extra behavior upstream does not have). The plan uses the refuse-to-start path.

The `file-env.sh` helper from upstream (`_FILE` env support) is sourced only if the server supports `*_FILE` variables (UNVERIFIED).

## 9. Rootless and read-only-rootfs adaptations

| Upstream write path | Remap |
| --- | --- |
| `/data` (covers, book bucket, app data; upstream `APP_DATA_PATH`) | Build-time symlink `/data -> /config/data` (root filesystem writable at build time) |
| `/books` (library, created by the image) | Build-time symlink `/books -> /config/books` |
| `/tmp` (node, pnpm store and corepack if used at runtime) | Runtime `--tmpfs /tmp`. Build-time caches stay in the build stage. |
| `/app/koreader-plugin`, `/app/public`, `/app/locales` | Read-only, served from the image. Nothing writes there. |
| Upstream root branch (`chown`, `su-exec`, `PUID`/`PGID`) | Dropped. The image runs as `apps`. The `/config` mount must be writable by UID 568 (documented in the PR). |

Draft security expectations reconciled: the chart runs as 568 (matches `apps`), `readOnlyRootFilesystem: true` (compatible, writes go to `/config` and `/tmp`), not privileged. The draft's `extra-persistence` (`/data/book-dock`, `/books`, `/data`) maps onto `/config` (`/config/data`, `/config/books`). UNVERIFIED: `book-dock` is a chart path with no upstream meaning that was found; check the chart before dropping it.

Run check: `docker run --read-only --tmpfs /tmp` with an empty `/config` must fail on the DB connection (expected) and not on a write error.

## 10. Risks, caveats and open questions

- Node version of the base (section 3). If the base's Node is older than the upstream `engines`, use option B.
- Upstream root branch removed. Existing users whose data was written by the upstream root start may need to `chown` their volumes to 568. Document in the PR.
- `kobo-cloudscraper` is a Python package with native dependencies; arm64 wheels are UNVERIFIED.
- `JWT_SECRET` and `SETUP_BOOTSTRAP_TOKEN` are required; the decision in section 7 must be made before implementing.
- The Dockerfile was reviewed at blob `c1dd6b4` (pre-3.10.0). Re-read the `v3.10.0` Dockerfile and `server/entrypoint.sh` at the tag before implementing (the lines 150-185 of the entrypoint were read at `c1dd6b4`).
- Heap: `NODE_MAX_OLD_SPACE_SIZE=2048` default may be too small on large libraries. The example value is kept.
- `ffmpeg` and `poppler-utils` add a large image size. Confirm they are required (audiobook and PDF paths) before keeping them.
- No blockers beyond these: no GPU, no privileged, no musl-only binary (Node and Python are glibc-compatible in the base).
