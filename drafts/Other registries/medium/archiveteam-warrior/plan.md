## 4. Dockerfile

1. Single stage on the python base from section 3: `ARG VERSION` (commit SHA), `USER root`.
2. apt: `git` (clone at build, not in python base if absent; check first). `--no-install-recommends`, clean lists.
3. `git clone https://github.com/ArchiveTeam/warrior-code2.git /tmp/src && git -C /tmp/src checkout ${VERSION}` (pin SHA; renovate git-refs updates it).
4. Install into the python base: `pip install /tmp/src` (or requirements from the repo) into /app/venv at build time, with `PIP_CACHE_DIR=/tmp/pip`. Do not write to /app/venv at runtime.
5. License to `/usr/share/licenses/archiveteam-warrior/LICENSE`.
6. `ENV HOME=/config` (or /tmp for scratch), `PYTHONDONTWRITEBYTECODE=1` (inherited from base).
7. Tail:

```dockerfile
USER apps
COPY --chmod=0755 . /

EXPOSE 8001
VOLUME /config
```

Do not carry the upstream grab-base wget-lua binaries (UNVERIFIED availability and arch). Note: run-warrior3 may need wget-lua to fetch items; this must be checked in step 3 (open question, section 10).

## 7. start.sh

- Idempotent. Create `/config/projects` and `/config/data` if missing (persistent). Seed `/config/projects/config.json` only when missing or empty (same logic as start.py), using env values.
- Never write to /app. Set `ulimit -c 0` as upstream entrypoint does.
- Bind 0.0.0.0 on 8001: run-warrior3 `--port 8001` (verify its default bind address in step 3).
- Final line: `exec run-warrior3 --projects-dir /config/projects --data-dir /config/data --warrior-hq https://warriorhq.archiveteam.org --port 8001 --real-shutdown`.
